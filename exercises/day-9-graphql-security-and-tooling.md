# Day 9: GraphQL Security and Best Practices (Project-Based)

## Topics
- Preventing expensive queries in Next.js API
- Input validation in mutations
- Securing your /api/graphql endpoint

## Exercises
1. Add input validation to your addMessageV2 mutation (e.g., restrict message length, block empty messages). Test error handling in the playground and UI.
2. Research and implement a simple query depth or complexity limiter for your Next.js GraphQL API route. Demonstrate blocking a deeply nested or expensive query.
3. (Bonus) Add basic authentication or API key protection to your /api/graphql endpoint. Test access from the playground and document the approach.
